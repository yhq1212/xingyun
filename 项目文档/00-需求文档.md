# 循环下载（Loop Download）功能需求文档

- 版本：v1.0（设计稿）
- 日期：2026-10-16
- 关联文档：`01-设计文档.md`、`02-工作记录.md`、`03-部署与迁移指南.md`
- 交付物名称：**WuLiao**（基于 AriaNg 前端二次开发，内置「循环下载」功能）；下文中的 *AriaNg* 指其底层前端框架。

---

## 1. 背景与目标

AriaNg 是 aria2 的现代化 Web 前端，通过 aria2 JSON-RPC 控制下载。aria2 本身只负责"下载一次"。
本需求希望在 AriaNg 上扩展一个 **循环下载** 功能：

> 给定一个或多个下载链接，反复下载 N 次；每次下载完成后在本地删除文件，然后继续下一次下载；
> 支持"自动开启"（启动即运行）、"循环次数"、"完成后自动关机/休眠"等控制，并具备状态监控与日志。

目标用户场景举例：
- 稳定性/带宽压测：反复拉取同一大文件，观察链路质量。
- 缓存/CDN 命中验证：每次都重新拉取，确保不是读缓存。
- 无人值守跑批：跑完指定次数后自动关机，省电省心。

---

## 2. 用户原始诉求（提炼）

1. 在 AriaNg 页面上增加一个功能入口。
2. 输入一个下载链接，可设置"反复循环下载"。
3. 下载完成 → 本地删除 → 继续下载。
4. 可设置：自动开启、循环次数、自动关闭（关机）等。
5. 用户自述"也有我没考虑到的地方，请你设计需求"。

## 4. 用户没考虑到、但必须设计的点（重点）

> 这些是项目能否落地的关键。第 4.1 条是决定整体架构的根本约束。

### 4.1 浏览器无法删除文件、也无法关机 —— 必须有一个本地辅助进程
AriaNg 是纯前端（HTML+JS），运行在浏览器沙箱里：
- **不能**删除用户磁盘上的任意文件；
- **不能**调用操作系统的关机/休眠；
- 标签页关闭，前端 JS 就停止运行。

因此，"下载完删除本地文件 + 自动关机"这两件事**不可能只靠网页完成**。
必须增加一个运行在本机的轻量辅助服务（本项目命名为 `loop-helper`，Node 实现，零第三方依赖），
由它负责：循环调度、删除文件、执行关机。AriaNg 网页只作为"配置面板 + 监控台"。

### 4.2 aria2 对已存在文件的处理
如果上次文件没删掉，aria2 再次下载同一路径会触发"断点续传/秒完成"，循环就失去意义。
所以"删除本地文件"是循环的**必要前置动作**，且删除必须在下一次 addUri 之前完成。

### 4.3 "下载完成"如何判定
- 优先用 aria2 的 `onDownloadComplete` 事件（WebSocket 推送，最及时）；
- 辅助服务侧采用**轮询 `tellStatus`** 判定 `status === 'complete'` / `'error'` / `'removed'`，更稳健、与前端解耦。

### 4.4 多文件 / BitTorrent 任务的删除粒度
单文件任务删除 `files[0].path`；BT 多文件任务 `files[]` 是一组路径，需逐个删除（或删除任务根目录）。
本项目按 `aria2 tellStatus` 返回的 `files[].path` 逐个删除，更安全。

### 4.5 删除安全性（防误删系统盘）
删除操作必须有边界：**仅允许删除 aria2 任务回报的文件路径，且必须在配置的"允许根目录"内**。
`loop-helper` 支持 `ALLOWED_ROOTS` 环境变量配置白名单；未配置时仅删除 aria2 回报的路径并打警告日志。

### 4.6 关机前的安全护栏
- 提供"测试关机"先验证；
- 默认"仅成功完成才关机"，避免出错也把机器关了；
- 关机命令仅在 localhost 辅助服务内部执行，外部无法触发。

### 4.7 防止重复并发循环
同一时间只允许一个循环任务。已有任务运行时，再次"开始"返回 409 拒绝。

### 4.8 aria2 断线/重连的处理
辅助服务与 aria2 之间若 RPC 失败，应：暂停循环、记录错误，待恢复后由用户手动重启（v1 不自动恢复，避免失控）。

### 4.9 单次下载超时
长时间卡住（如源站限速到 0）会导致循环挂死。提供 `PER_DOWNLOAD_TIMEOUT`（默认 0=不限）防止无限等待。

### 4.10 标签页关闭导致循环中断
因引擎放在本地 `loop-helper`，**即使关闭浏览器，循环仍继续**，满足"自动开启/无人值守"。

### 4.11 配置跨刷新/跨设备保留
- 循环配置：由 `loop-helper` 持久化到 `loop-helper/loop-config.json`；
- AriaNg 自身设置（如 helper 地址）：存浏览器 localStorage，换电脑需重新设置或导入。

### 4.12 多链接的循环策略
粘贴多个链接后，面板会出现「多个链接怎么处理」四选一：
- **每个链接独立循环（下完立即重下）**：每个链接一个独立 worker，谁下完谁就进入自己的下一轮，互不等待（**默认**）。适合"大小文件混合反复下载"——小文件不用等最慢的大文件；
- **每个链接都下载（一个一个来）**：顺序下载，一轮内每个链接各下一次，一轮全部完成后才进入下一轮；
- **每个链接都下载（同时下载）**：同一轮内同时下载，一轮结束后统一进入下一轮；
- **当作同一个文件的多个来源（镜像）**：只下一个文件，多个链接互为备用来源（aria2 镜像语义）。

独立循环模式的"次数"指每个链接各自下载几遍（总下载次数 = 链接数 × 次数）；其余三种模式一轮结束后统一删除该轮文件再进入下一轮。对应配置字段 `multiMode`（`independent` / `separate` / `concurrent` / `mirror`）。

### 4.13 日志可导出
运行日志可在面板查看；后续可导出为文本（扩展项）。

### 4.14 远程/移动端访问的边界
`loop-helper` 仅监听本机（localhost）。若从手机或其他电脑访问 AriaNg，删除/关机动作仍发生在**运行 aria2 的那台机器**上，符合预期。

### 4.15 局域网避让（避免占用整网带宽）
反复下载会拉低整个局域网的网速，影响同网段内的其他设备（如家人/同事在看视频、开会）。因此新增"局域网避让"能力：
- **探测手段**：循环前用 `os.networkInterfaces()` 取本机私有 IPv4 网段 → ping 整个子网让系统 ARP 表填充活跃设备 → 解析 `arp -a`（Win）/ `arp -n`（*nix）得到 `IP→MAC` 清单；剔除本机 IP 与网关，剩下的就是"其他在线设备"。该探测**纯 Node 内置模块 + 系统命令，零第三方依赖**（不破坏 `loop-helper` 零依赖约束）。探测结果带 TTL 缓存（默认 20s），避免每轮狂扫；探测失败一律 fail-open（返回 0 台，绝不因探测失败卡死下载）。
- **三种行为（用户可三选一）**：
  - `pause`（等待离线，默认推荐）：检测到其他设备在线 → 本轮**不下载**，进入 `waiting` 周期性重探；对方离线后自动恢复；
  - `throttle`（限速）：其他设备在线时，给本轮 aria2 任务附加 `max-download-limit`（如 `1M`，可配 `lanThrottleSpeed`）限速跑；无人时解除限速；
  - `ignore`（直接下载）：仅把探测结果显示在面板，不做任何避让。
- **配置**：`lanCheckEnabled`(开关)、`lanMode`(`pause|throttle|ignore`)、`lanThrottleSpeed`(如 `"1M"`)、`lanCheckInterval`(检测间隔秒)；随 `loopConfig` 持久化与校验。

> 说明：ARP 表只含近期通信过的设备；先 ping 全段再读 ARP 才能扫全。个别设备防火墙禁 ICMP 时可能漏检（后续可加探测兜底）；网关/本机已被排除，避免"永远有设备在线"。

## 5. 非功能需求（NFR）

- **可移植**：整个项目目录拷贝到新电脑（安装 Node 后）即可运行。
- **零额外依赖**：`loop-helper` 仅用 Node 内置模块，不需要 `npm install`。
- **安全**：删除与关机仅限本机、受白名单/确认保护。
- **兼容**：AriaNg 原有功能不受任何影响（新增独立路由与面板）。
- **轻量**：辅助服务常驻内存极小。

## 6. 验收标准

1. 启动 `start.bat` 后，AriaNg 出现"循环下载"入口。
2. 配置 1 个链接、次数=3、删除=开、间隔=2s，点击开始：
   - 页面能观察到次数 1→2→3 递增；
   - 每次完成后磁盘文件被删除，下一次是重新下载（大小从 0 开始）；
   - 第 3 次完成后循环停止。
3. 设置结束动作=关机，次数=1，点击开始：下载完成后电脑关机（先用"测试关机"验证命令可用）。
4. 勾选 autoStart 后，重启 `loop-helper`（不打开浏览器），循环自动开始。
5. 删除动作配置了 `ALLOWED_ROOTS` 后，试图删除白名单外路径会被拒绝并记录。
6. 手动停止可立即中止循环并移除当前下载任务。
7. 刷新浏览器后，配置与运行状态仍可恢复显示。
