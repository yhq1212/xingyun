# 循环下载（Loop Download）功能设计文档

- 版本：v1.0（设计稿 / 部分已实现）
- 日期：2026-10-16
- 交付物名称：**WuLiao**（基于 AriaNg 前端二次开发，内置「循环下载」功能）；下文中的 *AriaNg* 指其底层前端框架。

---

## 1. 总体架构

```
┌────────────────────────┐         REST (JSON, 含 CORS)        ┌──────────────────────────┐
│  浏览器：AriaNg 网页     │ ───────────────────────────────▶  │  本机 loop-helper 服务     │
│  (新增“循环下载”面板)    │ ◀───────────────────────────────  │  (Node.js, 零依赖)         │
│  配置 + 监控            │     状态/日志轮询 (2s)             │                          │
└────────────────────────┘                                    │  1) 循环调度引擎          │
                                                              │  2) 删除本地文件 (fs)     │
                                                              │  3) 关机/休眠 (exec)      │
                                                              └───────────┬──────────────┘
                                                                         │ aria2 JSON-RPC
                                                                         ▼
                                                              ┌──────────────────────────┐
                                                              │  aria2c (RPC :6800)       │
                                                              │  实际下载 → 写入磁盘       │
                                                              └──────────────────────────┘
```

**关键决策：循环引擎放在 `loop-helper`（本地 Node 服务），而不是浏览器前端。**
理由见需求文档 4.1/4.10：浏览器不能删文件、不能关机、关页就停。把引擎放本地，
既能实现“删除+关机”，又支持“自动开启/无人值守”（关掉浏览器循环照跑）。

AriaNg 侧只做两件事：① 把配置发给 helper；② 轮询 helper 的状态/日志来展示。
因此“功能加在 HTML 上”体现为：AriaNg 多了一个配置与监控面板，背后由 helper 执行。

## 3. 数据模型

### 3.1 循环配置 `loopConfig`（前端表单 ⇄ `POST /api/loop/config` 与 `/api/loop/start`）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `urls` | string[] | `[]` | 下载链接，每行一个 |
| `dir` | string | `''` | aria2 下载目录；开启删除时必填 |
| `out` | string | `''` | 可选文件名覆盖 |
| `options` | object | `{}` | 透传给 aria2 的额外选项（split/max-download-limit 等） |
| `maxCount` | number | `10` | 循环次数；`0` = 无限 |
| `intervalSeconds` | number | `5` | 每次完成后的等待秒数 |
| `randomDelay` | boolean | `false` | 间隔加入 0.5~1.5 倍随机抖动 |
| `deleteAfterComplete` | boolean | `true` | 完成后删除本地文件 |
| `stopOnError` | boolean | `true` | 下载出错是否停止循环 |
| `multiMode` | enum | `'independent'` | 多链接处理方式：`independent` 独立循环（每链接一个 worker，谁下完谁重下）、`separate` 顺序各下一个、`concurrent` 同时各下一个、`mirror` 多来源只下一个文件；旧 `concurrent` 布尔字段仍兼容 |
| `endAction` | enum | `'none'` | `none/shutdown/hibernate/sleep/logout/close-aria2/script` |
| `endActionScript` | string | `''` | `endAction=script` 时执行的脚本路径（`.bat/.cmd/.sh/.exe`） |
| `endActionScriptArgs` | string | `''` | 传给脚本的参数 |
| `endActionOnlyOnSuccess` | boolean | `true` | 仅成功完成才执行结束动作 |
| `notify` | boolean | `true` | 完成后弹浏览器通知（前端实现） |
| `autoStart` | boolean | `false` | helper 启动时自动开始 |
| `lanCheckEnabled` | boolean | `false` | 局域网避让开关 |
| `lanMode` | enum | `'pause'` | 避让方式：`pause` 等待对方离线再下载（默认）/ `throttle` 对方在线时限速 / `ignore` 直接下载（仅记录） |
| `lanThrottleSpeed` | string | `'1M'` | `lanMode=throttle` 时限速值（aria2 语法，如 `1M` / `500K`） |
| `lanCheckInterval` | number | `15` | 检测间隔（秒）；`pause` 模式下每这么久重探一次 |

### 3.2 运行状态 `state`（helper 内存 + `GET /api/loop/status` 返回）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `running` | boolean | 是否在运行 |
| `currentIteration` | number | 当前第几次 |
| `maxCount` | number | 目标次数（0=无限） |
| `phase` | enum | `idle/downloading/deleting/waiting/finished/error/stopped` |
| `currentGid` | string | 当前 aria2 任务 GID |
| `lastError` | string | 最近错误 |
| `config` | object | 当前生效配置 |
| `tasks` | array | 当前一轮的任务：`{gid, url, name, status, progress, speed, totalLength, completedLength, round}`；`round` 为独立循环模式下该链接自己的轮次 |
| `downloadedFiles` | array | 本次运行累计下载完成的文件完整路径（上限 500 条，持久化到 `loop-state.json`，供「清空全部」删除） |
| `downloadedCount` | number | `downloadedFiles` 当前条数（状态接口附带） |
| `startedAt` / `finishedAt` | string\|null | 本轮循环的开始/结束时间（ISO），用于前端显示“已用时间” |
| `log` | array | 最近 50 条日志 `{time, level, iteration, event, detail}` |
| `lanActive` | boolean | 当前是否检测到“其他在线设备” |
| `lanDevices` | number | 其他在线设备数量（不含本机/网关），状态卡实时展示 |
| `lanDetail` | array | 探测到的设备明细 `{ip, mac}`，供面板“立即扫描”结果展示 |

## 4. `loop-helper` REST API 契约

基础地址：`http://localhost:18888`（可用 `HELPER_PORT` 改）
所有响应为 JSON；支持 CORS（反射请求 Origin，方便 `file://` 直接调用）。
`OPTIONS` 预检返回 204。

| 方法 | 路径 | 请求体 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/health` | - | `{ ok:true, aria2:"host:port" }` |
| GET | `/api/lan/scan` | - | 手动触发一次局域网扫描，返回 `{ ok, selfIp, gateway, others, devices:[{ip,mac}] }`（`devices` 已剔除本机与网关）；面板“立即扫描”按钮调用 |
| GET | `/api/loop/status` | - | 返回 `state` |
| GET | `/api/loop/config` | - | 返回已保存配置 |
| POST | `/api/loop/config` | `loopConfig` | 校验并保存配置到 `loop-config.json` |
| POST | `/api/loop/start` | `loopConfig` | 启动循环；已在运行时返回 409 |
| POST | `/api/loop/stop?removeTask=true` | - | 优雅停止；`removeTask=true` 同时移除当前任务 |
| POST | `/api/helper/shutdown?dryRun=true` | - | 关机验证；`dryRun=true`(默认) 仅记录不执行 |
| POST | `/api/loop/log/clear` | - | 清空内存日志 |
| GET | `/api/loop/log/export?format=txt\|csv` | - | 导出**全部**日志（csv 带 UTF-8 BOM，Excel 可直接打开） |
| GET | `/api/helper/settings` | - | 返回 `{ allowedRoots: string[] }` |
| POST | `/api/helper/settings` | `{allowedRoots:string[]}` | 校验（必须绝对路径）并持久化到 `helper-settings.json`，**立即生效**（优先级高于环境变量 `ALLOWED_ROOTS`） |
| POST | `/api/helper/open-folder` | `{path:string}` | 在资源管理器中打开目录（Windows `explorer`；macOS `open`；Linux `xdg-open`） |
| POST | `/api/loop/history/clear` | - | 清空运行历史（仅清历史，`completedRounds` 保留） |
| POST | `/api/loop/cleanup` | - | **清空全部运行痕迹**：停止循环（等待引擎退出最多 15s）→ 按 `downloadedFiles` 清单删除已下载文件（含 `.aria2` 残留，逐一过白名单）→ 清零 `completedRounds`、清空历史/日志/任务列表，回到 idle |

**校验规则**（`validateConfig`）：
- `urls` 非空；
- `deleteAfterComplete` 为真时必须提供 `dir`；
- `maxCount` ≥0 整数；`intervalSeconds` ≥0；
- `endAction=script` 时 `endActionScript` 必填且文件必须存在。

## 5. 循环状态机

```
idle
 │ start
 ▼
downloading ──addUri──▶ (轮询 tellStatus)
 │ complete               │ error/removed/timeout
 ▼                       ▼
deleting              (stopOnError? → error→结束 ; 否则继续)
 │ deleteTaskFiles
 ▼
 (removeDownloadResult 清理)
 │ 还有次数?
 ├─ 是 ──▶ waiting ──sleep(interval)──▶ downloading
 └─ 否 ──▶ finished ──▶ doEndAction(endAction) ──▶ idle
stop ──▶ stopped（用户停止，不执行结束动作）
```

## 6. 文件删除安全策略

- 删除前调用 `isPathAllowed(path)`：
  - 若配置了 `ALLOWED_ROOTS`：路径必须落在某白名单根目录内（含子路径），否则拒绝并记日志；
  - 若未配置：仅允许删除 `aria2 tellStatus` 回报的文件路径（已在调用链保证来源可信），但记警告。
- 删除用 `fs.unlink`，忽略 `ENOENT`（文件已被清）；其它错误记日志。
- 多文件任务按 `files[].path` 逐个删除。

控制器用 `$http` 与 helper 通信（`parseUrlsFromOriginInput` 解析多链接，`confirm/showInfo/showError` 来自 `ariaNgCommonService`）。文案一律走 `'Key' | translate`，**键就是英文原文**，中文译在 `src/langs/zh_Hans.txt` 的 `[global]` 段；其它语言缺词条时自动回退为英文。

> ⚠️ **占位符语法（易错点）**：AriaNg 的 `translate` 过滤器来自 `pascalprecht.translate`（angular-translate），参数插值用的是**双花括号** `{{name}}`，不是单花括号。写法必须是
> `'Round {{current}}' | translate: {current: n}` + 语言包 `Round {{current}}=第 {{current}} 次`；
> 写成 `{current}` 不会被替换，页面会原样显示 `第 {current} 次`。可参考语言包里现成的 `settings.total-count=(共计: {{count}}个)`。

**界面设计原则（面向“小学生也能用”）**：
1. 进页面第一眼是**大状态卡**：图标 + 大号文字 + 进度条 + 速度/已用时间；
2. 配置拆成**三步**（粘链接 → 选目录 → 定次数），每步一张卡片、输入框够大；
3. 次数给**一键预设**（只跑 1 次 / 跑 10 次 / 一直跑），不必理解数字含义；
4. 所有专业选项（并发、随机抖动、出错停止、通知、文件名、结束动作、脚本）收进**「更多设置」折叠区**；
5. 有风险的能力（删除范围）单独放**「安全设置」**，白名单目录可视化增删。

## 9. 构建与运行流程

1. **改源码后必须重新构建 AriaNg**（见迁移指南第 4 节）：
   `npm install` → `gulp clean build-bundle` → 产物在 `dist/`，用其 `index.html` 覆盖根目录 `index.html`。
2. **最终用户运行（不改源码）**：双击 **`WuLiao.exe`**（单文件交付物，内置 Node 运行时 + aria2c + loop-helper，自动解压资源、拉起服务并打开界面 `http://localhost:6688`）。开发期仍可用 `start.bat` 一键启动（需本机已装 Node）。
3. 在 AriaNg「AriaNg 设置」中确认“Loop Download Helper URL = http://localhost:18888”。
4. 进入「循环下载」面板配置并“开始”。

## 11. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| `file://` 打开 AriaNg 时跨域调用 helper | helper 反射 Origin 并允许 `null` 源；或改用本地静态服务器 |
| aria2 未启动/端口不符 | 面板提示；helper 启动前确认 aria2 已起 |
| 误删文件 | `ALLOWED_ROOTS` 白名单 + 来源限制 |
| 关机误触发 | `dryRun` 测试 + 仅成功才关机 + 仅本机 |
| 改完源码忘了构建 | 迁移指南明确构建步骤；根 `index.html` 需替换 |
| 局域网避让漏检（个别设备防火墙禁 ICMP） | 先 ping 全段再读 ARP 已最大化覆盖；仍可能漏检少量设备。缓解：默认 `pause` 偏保守；如确需精确，可在路由器侧查看设备列表，或后续加 mDNS/SNMP 兜底探测（当前未做） |

### 12.1 历史功能与状态持久化（仅列 §3/§4 未覆盖的细节）

| 功能 | 实现方式 |
| --- | --- |
| 运行历史 / 统计 | 每轮结束把一条 `run` 记录写入 `loop-history.json`（最近 100 条）；状态接口附带 `history`（最近 50 条）与 `stats` 汇总 |
| 已完成轮次持久化 | `state.completedRounds` 每次成功后 `+1` 写入 `loop-state.json`，helper 重启后读回、计数不归零 |
| 独立循环模式 | `runIndependentLoop()`：每个链接一个 worker（下载→完成→删除→等待→重下），互不等待；`completedRounds` 按单次下载累加 |
| 实时进度/速度/已用时间 | `state.tasks`（含 `round` 轮次）+ `startedAt/finishedAt` |

`run` 记录结构：
```
{ id, startedAt, finishedAt, durationMs, urlCount, maxCount,
  deleteAfterComplete, endAction, multiMode, dir,

```
`endReason` ∈ `finished` / `stopped` / `error`（在改写 `running` 之前捕获，避免误判）。

## 13. 局域网避让（LAN Avoidance）

### 13.1 动机
反复下载会占满上行/下行带宽，拖慢同网段其他设备（家人看视频、同事开会等）。本功能在“每轮开始下载”之前加一道**局域网避让闸门**，按用户选择的行为处理，避免影响他人。

### 13.2 探测实现（`loop-helper/lan-probe.js`，零依赖）
- `os.networkInterfaces()` 取本机私有 IPv4 网段（仅取第一个 `10./172.16~31./192.168.` 且非回环、非 `/32` 的接口）；
- `enumerateHosts()` 由 IP + 子网掩码枚举该网段全部主机地址（剔除网络/广播地址）；
- `pingSweep()` 并发（默认 32）`ping` 整段（Win `ping -n 1 -w 200 <ip>` / *nix `ping -c 1 -W 1 <ip>`），目的是让系统 ARP 表填充活跃设备；
- `readArp()` 解析 `arp -a`（Win）/ `arp -n`（*nix）得到 `IP→MAC`；
- `getGateway()` 用 `route print 0.0.0.0`（兜底 `netstat -rn`）取网关；
- 最终剔除**本机 IP** 与**网关**，余下即“其他在线设备”数量 `others`。
- 结果带 **20s TTL 缓存**，避免每轮重复全段 ping；探测异常（命令失败/超时）一律 **fail-open** 返回 `others=0`，绝不因探测失败卡死下载。

> ⚠️ **已踩坑（JS 有符号按位运算）**：`isPrivate()` 用 `(n & 0xffff0000) === 0xc0a80000` 判断 `192.168` 段时，因 JS 按位运算返回**有符号** 32 位整数（高位为 1 时为负），与无符号字面量比较恒为 `false`，导致 `192.168/172.16` 网段被误判为“非私网”而不扫描。已统一用 `>>> 0` 转无符号后再比较。

### 13.3 闸门逻辑（`lanPreDownload(config)`）
在主循环每轮 `runRound` 之前、以及独立循环每个 worker 的 `addUri` 之前调用：
- `lanCheckEnabled=false` → 直接放行，且 `state.lanActive=false / lanDevices=0`；
- 开启后循环扫描（每次重检 `force=true` 绕过缓存），并更新 `state.lanActive / lanDevices / lanDetail`；
- `others===0` → 放行；
- `others>0` 且 `mode=pause` → 置 `phase=waiting`，记日志后 `sleepInterruptible(lanCheckInterval*1000)` 再重探，直到对方离线或用户停止（停止则 `proceed=false`，调用方 break）；
- `others>0` 且 `mode=throttle` → 放行，并在 `extra` 中加入 `max-download-limit = lanThrottleSpeed`，透传给 `buildAddOptions` → `addUri`；
- `others>0` 且 `mode=ignore` → 放行（不动限速，仅展示）。

### 13.4 前端（`loop-download` 面板）
- 「局域网避让」独立折叠面板（位于「更多设置」与「安全设置」之间）：开关 + 三选一单选 + 限速值输入框（仅 throttle 显示）+ 检测间隔 + “立即扫描”按钮 + 扫描结果列表；
- 状态卡 `hero-meta` 在运行时实时显示“N 台其他设备在线”；
- 配置随 `buildPayload` 进入 `loopConfig` 并持久化（含归一化校验）。
