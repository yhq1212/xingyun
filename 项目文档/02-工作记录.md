## 1. 项目概况

- 目标：在 AriaNg 上加"循环下载"功能（反复下载 → 删本地 → 再下；可设次数 / 自动开启 / 自动关机）。
- 根本约束：浏览器前端不能删文件 / 关机 → 引入本地辅助服务 `loop-helper`（Node，零依赖）。
- 架构：AriaNg(面板) ──REST──▶ loop-helper(引擎 / 删文件 / 关机) ──RPC──▶ aria2c(下载)。

## 3. 关键决策

- **循环引擎放在本地 helper 而非浏览器**：浏览器不能删文件、不能关机、关页就停（需求文档 4.1/4.10）。
- **独立循环模式（默认）**：多链接时每个链接一个 worker 互不等待，谁下完谁重下——解决"exe 几秒下完却要等几小时的 ISO"的体验问题。轮次制（顺序/并发/镜像）仍保留可选。
- **"清空全部"基于文件清单**：每次下载完成时把文件路径记录到 `loop-state.json`（上限 500 条），清理时按清单删除并逐一过白名单校验，避免整目录误删。
- **带参数的翻译必须在控制器 JS 里调用** `translate(key, params)`（见踩坑第 1 条）。
- **局域网避让用"原生零依赖"实现，不引 npm 包**：GitHub 上成熟的 Node 内网探测库（如 `local-devices`）带 3 个依赖，会破坏 `loop-helper` 零依赖约束；其底层就是 `os.networkInterfaces()` + ping 全段 + 读 ARP，可自己写。探测 fail-open（出错返回 0 台），不卡下载。

## 4. 踩坑经验（必读，均为实际踩过的坑）

1. **translate 占位符两个限制**：① 必须双花括号 `{{name}}`（angular-translate），单花括号不替换；② **带 `{{}}` 的翻译键不能写在指令属性里**——AngularJS `$compile` 会先对属性内 `{{}}` 做插值，把键破坏成空串。所以带参翻译一律放控制器 JS，视图只调用 `roundLabel()` 这类无参函数。
2. **新增 JS 文件必须登记到 `src/index.html` 的 `build:js` 块**，否则不进 bundle（症状：`{{ }}` 原样显示、控件点不动）。视图 `views/*.html` 与语言包自动收集，无需登记。
3. **复选框/单选钮结构**：AriaNg 用 awesome-bootstrap-checkbox，要求 `<input>` 与 `<label>` 为兄弟节点且 `id`/`for` 对应，写成 `label > input` 会点不动。
4. **改源码后的生效条件**：改 `AriaNg-master/src` → 必须重新构建并覆盖根 `index.html`（且浏览器 Ctrl+F5）；改 `loop-helper/server.js` → 必须重启 helper。否则"新功能报 not found / 不生效"都是这个原因。
5. **`POST /api/loop/start` 会顺带保存配置**（覆盖 `loop-config.json`）。旧页面对新配置文件做"开始"会把新值覆盖回旧值——排查"功能没生效"时先看这个文件里实际存的是什么。
6. `file://` 打开 AriaNg 调 helper 的跨域：helper 已做 Origin 反射兼容 `null` 源；个别浏览器拦截时改用本地静态服务器打开。
7. 测试用文件服务器需支持 HTTP Range（aria2 默认多连接分片），否则出现假失败。
8. `stopOnError` 触发与用户停止都要在改写 `state.running` **之前**捕获结束原因，否则历史 `endReason` 误判。
9. **pkg 打包依赖 GitHub 上的「补丁版 Node」**：pkg 不是用普通 node，而是需要 `vercel/pkg-fetch` releases 里的 `node-v18.5.0-win-x64`（约 64MB），且**带 SHA256 校验**——把官方 node（含项目里 `node-v24.22.0`）放进 pkg 缓存会被判哈希不符、删掉重新下载，**替换无效**。**腾讯云 / npmmirror / ghproxy 等境内镜像都不托管该补丁版二进制**，"用腾讯云镜像加速打包"走不通；直连 GitHub 慢但可用，或改用 IExpress 零下载（见 §7）。
10. **JS 按位运算是有符号 32 位（局域网探测踩坑）**：`lan-probe.js` 的 `isPrivate()` 判断私网段时，初版写成 `(n & 0xffff0000) === 0xc0a80000`。但 JS `&` 返回**有符号** 32 位整数，`192.168.x.x`（`0xC0A8xxxx`）高位为 1，结果是**负数**，与无符号字面量 `0xc0a80000`（正数）永不相等 → `192.168/172.16` 网段被误判为“非私网”，整段不扫描、永远 `others=0`（失效）。**统一用 `(n & MASK) >>> 0` 转回无符号后再比较**即修复。同理 `*nix` 防火墙禁 ICMP 时 ARP 可能漏检，属预期局限。

## 6. 下次继续时怎么做

1. **最终用户**：拷贝 `WuLiao.exe`（或整个目录）→ 双击 `WuLiao.exe`（自动解压、起服务、开浏览器）；默认英文，可在设置里切简体中文。
2. **开发/改源码**：装 Node.js（≥12）→ 拷贝整个项目目录。
3. 改过 `AriaNg-master/src`：`cd AriaNg-master && npm install && gulp clean build-bundle`，用 `dist/index.html` 覆盖根 `index.html`。
4. 改过 `loop-helper/server.js`：重启辅助服务（重开 `WuLiao.exe` 或重跑 `start.bat`）。
5. 重新打包交付物：`cd build && npx --yes pkg@5.8.1 launcher.js --targets node18-win-x64 --assets "res/**/*" --output WuLiao.exe`，再拷到根目录（详见 `03-部署与迁移指南.md` §5.2）。⚠️ 该命令需从 GitHub 拉「补丁版 Node」（约 64MB，境内镜像不行）；若联网不便，改用项目内 `node-v24.22.0` + Windows 自带 `IExpress` 零下载打包（见 §7）。
6. 打开 AriaNg → 设置 Helper URL → 循环下载面板。

> 开发/迁移细节见 `03-部署与迁移指南.md`，接口与数据结构见 `01-设计文档.md`。

## 7. EXE 打包经验总结（专项）

**目标**：把 aria2c + loop-helper + AriaNg 前端 + Node 运行时打包成单文件 `WuLiao.exe`，对方双击即用、无需安装 Node。

**选型与现状**
- 首选 `pkg`：自带补丁版 Node 运行时，解压一次到 `<exedir>/_wuliao_runtime`（端口 6688 / 6800 / 18888），体验最好；但首次需从 GitHub 拉「补丁版 Node」二进制（约 64MB）。
- 现状：本机直连 GitHub 下载曾在 ~22MB 处停滞，EXE 实体**尚未生成**；需重跑（直连）或切备选方案。

**关键踩坑（已实测）**
1. pkg 的 Node **不是**普通 node，而是 `vercel/pkg-fetch` releases 上的补丁版 `node-v18.5.0-win-x64`，**带 SHA256 校验**。把官方 node（含项目里 `node-v24.22.0/node.exe`）放进 pkg 缓存会被判哈希不符、删掉重下——**替换无效**。
2. **境内镜像（腾讯云 `mirrors.cloud.tencent.com`、npmmirror `cdn.npmmirror.com/binaries`、ghproxy 等）均不托管该补丁版二进制**；`github-release` / `binaries` 路径实测全部失败，"用腾讯云镜像加速打包"客观上走不通。
3. 直连 GitHub 通常可达但较慢（几十 MB，可能数分钟），偶发停滞——重跑即可。

**零下载兜底方案（IExpress）**
- 用项目内 `node-v24.22.0/node.exe` + Windows 自带的 `IExpress`（`%WINDIR%\System32\iexpress.exe` / `sfxmake.exe`）把 `node.exe` + `launcher.js` + `aria2c.exe` + `index.html` + `loop-helper/` 打成自解压单文件 EXE（指令文件 `.sed` + `iexpress /N /Q xxx.sed`）。
- 优点：全程不联网，正好用上你准备的 node。
- 注意：每次启动会解压到临时目录（约百 MB，几秒）；运行时数据（下载文件、计数、日志）应固定写到 `%LOCALAPPDATA%\WuLiao` 而非随解压目录，否则每次启动丢数据。

**决策建议**：能联网就直连 GitHub 跑 pkg（体验最好）；完全离线 / 不想等下载，就用 IExpress + 项目内 node 兜底。
